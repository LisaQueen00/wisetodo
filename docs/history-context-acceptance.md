# 长 Session 上下文验收

## 当前策略

Runtime 在组装当前 Session 的 user/assistant 历史后，调用 `bounded_history`；随后再加入 URL 资料、真实编辑目标和系统规则。只裁剪发送给模型的副本，不覆盖 SQLite 历史，不额外请求模型总结。

- 历史正文总量不超过 32,000 个 Python 字符，最多 64 条。
- 单条正文超过 8,000 字符时保留头尾，中间插入省略标记。
- 保留第一条消息（通常是原始目标），其余从最近消息向前连续选取；达到条数或字符限制即停止，再按原顺序发送。
- 发生任何省略时，在第一条前加明确提示，要求必要事实不足时澄清。总预算包含标记；第一条因提示可略超单条裁剪长度。
- 角色不变，system 消息不允许进入此函数。完整工具调用链不经此历史裁剪器处理。

这是一种有损裁剪，不是语义摘要。中间消息的约束和超长正文中部的事实可能丢失，不能保证模型主动澄清或保留全部语义。当前限制是代码常量，不增加用户配置负担。

字符不是 Token：本策略不承诺适配所有模型上下文窗口。系统提示、Skill、工具定义/结果、URL 资料和目标快照有独立来源，不包含在这 32,000 字符额度内。数据库仍全量保存和加载，因此也不代表存储或加载内存有上限。
