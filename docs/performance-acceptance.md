# 大列表与自动保存测试

## 可重复自动化

```powershell
pnpm.cmd exec vitest run src/todos/TodoPerformance.test.tsx src/lib/debouncedSave.test.ts --reporter=verbose --silent=false
```

列表使用真实 TodoList/TodoCard，显示编辑、删除、排序按钮，mutation 为 mock，不连接用户数据库。每个 Todo 有 10 个子项，20% 已完成。验证全部行存在、分组稳定、展开后子项齐全、折叠不丢行；折叠子项不挂载 DOM。

2026-09-10 本机 Windows、Vitest/jsdom 单次采样（毫秒）：

| Todo 数量 | 首次渲染 | 展开一项 | 再次折叠后 DOM 节点 |
| --- | --- | --- | --- |
| 100 | 81.6 | 56.8 | 2,072 |
| 1,000 | 427.8 | 109.1 | 20,612 |

这是开发测试环境的同步 React/DOM 操作耗时，不含浏览器布局绘制、IPC、SQLite 或加载数据时间；不是多次采样的中位数/P95，也不是桌面帧率。测试不设易受机器负载影响的毫秒断言。全量列表未虚拟化，千项场景仍有较大的 DOM 与更新成本，不能视为已完成性能优化。

自动保存使用虚拟时钟检查请求放大与串行性，不测真实磁盘速度：

- 每隔 1 ms 输入一次，共 1,000 次；停顿 400 ms 后仅写最后一次值，随后 flush 不重复写。
- 第一笔保存未返回时再输入 1,000 次；后续写入等待第一笔完成，最终仅写入初始值和最新值。
- 保留既有立即 flush、取消待保存、重叠保存串行测试。

边界：慢保存期间如果出现多次超过防抖间隔的停顿，仍可能排入多个快照；本次测试不证明任意持续慢请求下队列长度有上限。

## 真实桌面验收仍待进行

在独立测试数据目录使用发布构建，分别准备 100/1,000 项，避免污染日常数据。记录机器配置、数据量，重复测量首次显示与展开响应，检查连续滚动、编辑和勾选是否卡顿；编辑停止后检查保存状态并重启核对最终文本。另测慢 IPC/磁盘下的输入响应与保存延迟。当前自动化不替代这些测量，不宣称生产体验验收通过。
