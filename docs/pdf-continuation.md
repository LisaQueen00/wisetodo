# PDF 目录与页面续读

反馈：完整原书却只生成到部分章节，模型要求用户提供后续目录。已确认代码存在三层有界提取：200 条书签、前三页每页 4000 字符、模型 JSON 12000 字符。旧版没有续读参数，且 PDF 一批读取后被强制收敛。没有取得用户原书，不能断定该书具体在哪层被裁剪。

新版仍保留资源限制，但允许安全续读：

```json
{"file_ref":"本次附件引用","mode":"outline","outline_depth":0,"outline_offset":0}
```

读取顶层书签；若只有书名包装节点，增加 outline_depth（0–16）并归零偏移。next_outline_offset 非空时传入 outline_offset 读取同一层级的下一段。outline_complete 仅表示该层级书签读取完整，不保证 PDF 书签本身忠实覆盖印刷目录。按章计划不需要读完数百条小节。

```json
{"file_ref":"本次附件引用","mode":"pages","start_page":4,"text_offset":0}
```

无书签时按物理页读取印刷目录；每次最多三页，每页最多 4000 字符。长页面截断则 next_page 仍为当前页，next_text_offset 指向下一段；将两者分别传回 start_page、text_offset。短页读完后前进到下一页。超出总 JSON 预算而被省略的页面也返回对应指针，不跳过未交付内容。

partial 始终表示只取得有限资料，不代表原书缺页或目录不完整。目录模式不混入正文，减少预算竞争。新版 Runtime 支持续读，最多八批且重复请求/重复结果收敛；并不承诺任意大 PDF 都能一次生成全书计划。扫描页没有文字时仍无 OCR，不能伪造章节。

保留附件引用白名单、64 MiB 文件上限、独立 worker、25 秒工具内超时、取消清理和输出预算。旧自定义 parse_pdf Schema 若只有 file_ref，不会自动获得新参数；需要用户更新配置，应用不擅自覆盖。

测试使用生成的本地 PDF 和模拟模型：超过 200 条书签、章级筛选、结果预算裁剪、第四页后续读、同页文本续读、两种模型模式的真实 worker 连续读取。未调用付费模型，也未读取用户原书。
