# Phase 8.6：依赖式项目规划

## 执行规则

- 已给公开 GitHub 仓库根链接：读取仓库资料，再生成一个 Todo。
- 已给明确项目名：搜索定位，唯一明确匹配时继续读取；歧义时澄清。
- 仅给学习方向：搜索真实候选，请用户选择一个；用户选择后下一轮读取。不是为每个候选批量生成任务。

Runtime 不再在第一批搜索后立即禁止所有工具。包含 `search_projects` 的批次结束后，可继续调用下一批；最多三批工具，之后强制进入无工具最终阶段。普通读取后直接收敛到 Todo/clarification，避免无目的工具循环。正常搜索→读取→生成需要三次模型请求，原先一到两次是优化目标，不再妨碍依赖执行。一次 Run 的输出修复额度仍共享且只有一次。

原生模式保留 assistant/tool 消息配对；兼容模式携带结构化工具结果。既有取消、失败不提交、待提交结果持久化与免模型重试机制继续适用。明确编辑目标限制不变。

项目搜索仅使用现有公开 GitHub 搜索，不新增付费搜索商或假设模型内置联网。泛网页搜索、任意多跳网页浏览不包含在本项中。

## 仓库事实范围

读取 README、常见贡献指南、根目录和有限 issue，并对实际存在的 src/lib/docs/examples/tests 中最多三个目录列举各最多十五个二层条目。路径请求采用固定目录白名单，不执行项目代码。资料总量仍受原有预算限制，`partial` 明确保留；构建/运行事项依据 README 等真实资料，不推测不存在的命令。

内置学习/贡献 Skill 与系统提示同步更新，不再保留“一批工具后禁止继续读取”的矛盾指令。计划具体性和唯一匹配判断仍由模型处理，不能凭离线测试承诺任意项目的语义质量。


新增六项用例覆盖两种模式的搜索→读取→提交、提交失败后免工具/免模型重试、三批上限；复用方向澄清/选定后读取、缺失资料、无工具和取消失败测试。全部模拟 Provider/HTTP，无真实模型调用。

新可执行文件位于 `src-tauri/target/phase86/release/wisetodo.exe`，需与同目录 `wisetodo-sidecar.exe` 一起使用。安装包在该目录的 `bundle/nsis/`。先彻底退出旧版再启动，防止单实例唤起旧进程。

建议人工测试：给明确仓库根 URL；只给一个明确项目名；只给语言/学习方向后选择候选。查看执行记录是否依次搜索和读取，核对 Todo 引用真实模块而非通用口号。真实模型效果待用户确认，不自动消耗 Token。
